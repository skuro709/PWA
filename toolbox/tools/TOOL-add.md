# ツール追加・変更ガイド

SK TOOLBOX に新しいツールを追加したり、既存ツールの名前・ファイル名・アイコンを変更したりするときの手順書です。

## 1. 現在のファイル構成と役割

現在の実装では、ツールの表示情報と実際の実行処理は別々に管理されています。

| ファイル | 役割 |
|---|---|
| `data/tool-registry.js` | ツールID、表示名、カテゴリ、説明、検索語、アイコンなどを登録 |
| `assets/js/tool-runner.js` | ツールごとの入力欄と実行処理を定義 |
| `tools/<category>/<tool-id>/tool.js` | ツールごとのファイルを配置する場所 |
| `assets/js/app.js` | 画面表示、一覧、検索、アイコン描画、画面遷移 |
| `assets/icons/tool-symbols/` | ツールカードで使用するSVGアイコン |
| `sw.js` | オフライン用キャッシュの管理 |

**重要：現在の実装では、`tools/` 内の `tool.js` は `tool-runner.js` から自動的に読み込まれていません。**

そのため、ツールの実際の処理は `assets/js/tool-runner.js` に追加する必要があります。

---

## 2. 新しいツールを追加する手順

例として、`text-trim`（テキストの前後空白削除）を追加します。

### 手順1：ツールIDを決める

- 英小文字とハイフンを使用する
- 既存IDと重複させない
- カテゴリを先頭につけることを推奨

例：`text-trim`

### 手順2：ツール用フォルダとファイルを作る

カテゴリに対応するフォルダを作成します。

```text
tools/
└── text/
    └── text-trim/
        └── tool.js
```

現在、このファイルは配置・整理用です。

実際の処理は次の手順で `tool-runner.js` に追加します。

### 手順3：tool-registry.js に登録する

`data/tool-registry.js` の `TOOL_REGISTRY` 配列に、次のようなオブジェクトを追加します。

```js
{
  id: "text-trim",
  name: "空白削除",
  category: "text",
  description: "行頭・行末の空白を削除",
  keywords: ["空白削除", "トリム", "テキスト"],
  offline: true,
  icon: "textformat"
}
```

確認事項：

- `id` は `tool-runner.js` の定義と完全一致させる
- `category` は既存カテゴリを使用する
- `icon` はSVGファイル名から拡張子を除いた名前にする
- `keywords` には検索で使われそうな言葉を入れる
- `id` はお気に入りや履歴との対応に使われるため、公開後はなるべく変更しない

### 手順4：tool-runner.js に実行処理を追加する

`assets/js/tool-runner.js` の `defs` の中に、登録したIDと同じキーを追加します。

```js
'text-trim': {
  fields: [
    { id: 'text', label: 'テキスト', type: 'textarea' }
  ],
  run: () => out(
    val('text')
      .split('\n')
      .map(line => line.trim())
      .join('\n')
  )
},
```

基本的な仕組み：

- `fields`：入力欄の定義
- `run`：実行処理
- `val('text')`：入力値を取得
- `out(...)`：結果を表示

非同期処理が必要な場合は `run: async () => { ... }` を使用できます。

※上記は追加方法の例です。実際の関数名や構造は、既存の `tool-runner.js` に合わせてください。

### 手順5：SVGアイコンを追加する

`tool-registry.js` の `icon` が `text-trim` の場合、次のファイルを用意します。

```text
assets/icons/tool-symbols/text-trim.svg
```

確認事項：

- `icon` の値とSVGファイル名を一致させる
- SVGはアプリ内に配置する
- 既存のSVGアイコンを再利用してもよい
- 絵文字は使用しない

PNGを使用する場合は、現在のSVG読み込み処理を変更する必要があります。PNGを追加するだけでは表示されません。

### 手順6：sw.js のキャッシュを確認する

新しいファイルがService Workerのキャッシュ一覧に列挙されている場合は、必要に応じて追加します。

- 新しい `tools/.../tool.js`
- 新しいSVGアイコン
- ツールが必要とするローカルライブラリ

ファイル一覧が自動生成される仕組みの場合、手動追加は不要です。

更新時にはキャッシュ名のバージョンも更新します。

※既存のIndexedDBデータを消す処理は追加しないでください。

## 3. 既存ツールのファイル名・フォルダ名を変更する場合

| 変更するもの | 確認・変更する場所 |
|---|---|
| `tool.js` のファイル名 | `sw.js` のキャッシュ一覧 |
| ツールフォルダ名 | `sw.js` のキャッシュ一覧やパス参照 |
| カテゴリフォルダ名 | `sw.js` やパス参照 |
| ツールID | `tool-registry.js`、`tool-runner.js`、保存データとの整合性 |
| 表示名 | `tool-registry.js` |
| 説明文 | `tool-registry.js` |
| 検索キーワード | `tool-registry.js` |
| アイコン名 | `tool-registry.js` とSVGファイル名 |
| ページHTML名 | `app.js` の読み込み処理とルーティング設定 |

**おすすめ：ツールIDは公開後に変更しないでください。**

表示名だけを変更する方が安全です。

## 4. 新しいカテゴリを追加する場合

新カテゴリを作成する場合は、次の場所を確認します。

1. `tool-registry.js` の該当ツールに新しい `category` を設定する
2. `assets/js/app.js` の `cats` にカテゴリIDと表示名を追加する
3. `tools/<new-category>/` にツール用フォルダを作成する
4. 必要に応じてカテゴリ用CSSを追加する
5. `sw.js` のキャッシュ対象を確認する

カテゴリIDは英小文字で統一し、レジストリと `app.js` のキーを一致させます。

## 5. ツール追加後の確認チェックリスト

- [ ] `tool-registry.js` にツールが登録されている
- [ ] ツールIDが重複していない
- [ ] `tool-runner.js` に同じIDの実行処理がある
- [ ] ツール一覧に表示される
- [ ] 検索キーワードで検索できる
- [ ] アイコンが正しく表示される
- [ ] 入力欄が正しく表示される
- [ ] 実行ボタンが動作する
- [ ] 結果が正しく表示される
- [ ] コピー・リセットが動作する
- [ ] お気に入りが動作する
- [ ] 履歴が動作する
- [ ] 再読み込み後も必要なデータが残る
- [ ] オフラインでも必要な機能が動作する
- [ ] iPhone Safariで表示を確認する
- [ ] デスクトップブラウザでも表示を確認する

## 6. ローカルでテストする

プロジェクトのルートでローカルHTTPサーバーを起動します。

```bash
python3 -m http.server 8080
```

ブラウザで次のURLを開きます。

`http://localhost:8080/`

`file://` で直接HTMLを開く方法では、ES ModulesやService Workerなどの動作を正しく確認できない場合があります。

## 7. よくある問題

| 症状 | 確認すること |
|---|---|
| ツール一覧に表示されない | `tool-registry.js` の登録内容 |
| 入力欄は表示されるが実行できない | `tool-runner.js` のIDと処理 |
| アイコンが表示されない | `icon` とSVGファイル名、配置パス |
| 更新したのに古い表示になる | `sw.js` のキャッシュ名・キャッシュ対象 |
| お気に入りや履歴が見つからない | ツールIDを変更していないか |
| オフラインで動かない | 必要なJS・SVG・ライブラリがキャッシュされているか |

## 8. 将来の改善案：ツールを完全な独立モジュールにする

将来的には、各ツールの実行処理を次の場所に移す方式がおすすめです。

```text
tools/
└── <category>/
    └── <tool-id>/
        └── tool.js
```

共通の `tool-runner.js` が各ツールの `tool.js` を動的に読み込む構成にすれば、新しいツールを追加するたびに `tool-runner.js` を編集する必要がなくなります。

ただし、これは現在の実装ではありません。

実施する場合は、全ツールで共通のモジュール仕様を決め、既存ツールを順番に移行し、エラー処理・キャッシュ・画面遷移も合わせてテストしてください。

移行が完了するまでは、このガイドの「2. 新しいツールを追加する手順」に従ってください。
